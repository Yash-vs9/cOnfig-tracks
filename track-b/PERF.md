### Notes on Step Progression
- **Step 1:** Initial port to multi-threaded C++20 using `mmap` zero-copy I/O and standard positional posting lists. Cut runtime by 4.7x ($T: 56.35\text{s} \to 12.00\text{s}$) and memory by 11.5x ($M: 2,200\text{MB} \to 190\text{MB}$).
- **Step 2:** Adopted Option B for phrase queries per Section 3 and 8 of the specification. Eliminated the 100 MB positional index entirely and indexed only the ~75.7k distinct terms present in `queries.txt`. Phrase queries intersect candidate document lists and verify consecutive tokens on-the-fly against the `mmap` text slice.
- **Step 3:** Replaced uncompressed `uint32_t` postings with a hybrid representation: 250k-bit bitsets for top terms ($df > 15,625$) and 12-chunk CSR arrays of `uint16_t` postings for remaining terms. Enforced strict 2-pass memory reuse via `munmap` to avoid peak spikes during indexing. This reduced peak memory to **44.5 MB**, hitting the maximum 50x score cap ($50^{0.20} = 2.1867\times$) and boosting $K$ to **6.25**.
- **Step 4:** Diagnosed and crushed three profile bottlenecks:
  1. *Docs Offset Scan ($244\text{ms} \to 1.7\text{ms}$):* Sliced the file into 12 64-aligned byte chunks in $O(1)$, recording `doc_text_start` in parallel during Pass 1.
  2. *Phrase Query Verification ($1,353\text{ms} \to 854\text{ms}$):* Replaced expensive FNV-1a hashing and 44M `vocab_lookup` probes during candidate verification with zero-allocation `(ptr, len)` tokenization and instant length + first-character rejection.
  3. *8-Byte Cache-Aligned Vocab Slots ($1.04\text{MB}$ total):* Packed `hash32` and `term_id` into 8-byte slots (8 per 64-byte L1 cache line) with a companion `TermInfo` table, minimizing L2/L3 cache misses.
  Total engine process time dropped under 3 seconds ($2.98\text{ s}$), container run dropped to **$3.23\text{ s}$**, and $K$ rose to **$7.18\times$** ($42.8$ Speed Points).
- **Step 5:** Implemented three major algorithmic and code architecture wins:
  1. *Virtual Repeat Terms (Win 1):* Identified that phrases with repeated words (e.g., `PHRASE "falbris falbris"`) produced up to 1,071 false-positive candidates because individual terms had high frequency while the repeated pair was ultra-rare. By registering virtual repeat term IDs in the normal index during query parsing and detecting consecutive occurrences in documents, phrase candidate evaluations dropped by > 95%, cutting query CPU time by over 50%.
  2. *Dual-Mode Sorted uint16_t Fast-Path for BOOL queries (Win 2):* Evaluated queries starting with sparse terms directly on the stack via in-place two-pointer set operations and bitset tests ($O(|R|)$), avoiding the overhead of zeroing and scanning 326-word bitsets across 12 chunks.
  3. *Deduplicated Shared Template Tokenizer & Unified BOOL Evaluator (Win 3):* Consolidated Pass 1 and Pass 2 tokenization into a shared inline template (`scan_doc_tokens`), unified bitset operations into single loops, and trimmed redundant arrays. Reduced `solution.cpp` from 811 to 646 lines ($S$ factor improvement) while maintaining 100% exact SHA-256 match and $M \le 44.5\text{ MB}$.
  Total container runtime dropped to **$0.565\text{ s}$** on the official board runner (`run-3a1427d8f3c6`), yielding $K \approx 15.20\times$ and **$59.09$ Speed Points**.
- **Step 6:** Migrated the engine entirely to safe, zero-dependency Rust (`run-072c925946a9`). Established two-pass CSR postings layout, SWAR hashing, and multi-threaded query execution, recording $T = 0.600\text{ s}$, $M = 57.9\text{ MB}$, and **$57.55$ Speed Points**.
- **Step 7:** Optimized memory footprint and inner loop CPU cache locality (`run-c078fc16c3d3`). Reused Pass 1 frequency buffers in place for the CSR offset tables, eliminating the 3.66 MB `cur_co` buffer. Implemented `MaybeUninit` to bypass 4.8 GB of cumulative stack zeroing per run, enforced `mallopt(M_ARENA_MAX, 2)` to eliminate thread arena bloat, and switched to contiguous row-major index access. Peak memory dropped to **51.7 MB** (-6.2 MB), wall time improved to **0.574 s**, and score advanced to **$58.32$ Speed Points**.
- **Step 8:** Replaced per-thread concurrent heap allocations with a unified scratch buffer `all_scratch` reused between Pass 1 and Pass 2 and explicitly dropped prior to query execution (`run-8e4258485f94`). Reduced code by 176 lines to 812 LOC. Scored $T = 0.581\text{ s}$, $M = 62.9\text{ MB}$, and $57.96$ Speed Points.
- **Step 9:** Resolved anonymous memory ceiling towards 43.99 MB 50x cap zone (`run-1e7feec2852c`). Configured 128 KB thread stacks via `std::thread::Builder::new().stack_size(131072)` (eliminating 22.5 MB of glibc 2 MB thread stack cache). Completely eliminated `all_scratch` (3.65 MB) by reusing `c_off` directly as the Pass 2 cursor, moving prefix start to end in-place. Switched Pass 1 & Pass 2 deduplication to thread-scoped 152 KB `seen` vectors, converting random DRAM reads during Pass 2 into instant L2 cache hits. Cut peak memory from 62.95 MB to 52.27 MB (-10.7 MB) and improved wall time to 0.563 s, achieving a new team record $K = 15.22$ and 59.12 Speed Points.
- **Step 10:** Aligned indexing partition granularity directly to the 6 physical P-cores (`NUM_C = 6`), avoiding hyper-threading cache contention and halving `c_off` offset buffer from 3.65 MB down to 1.82 MB (-1.83 MB) (`run-aef8179f86fb`). Converted `seen` deduplication arrays into 100% stack-allocated `[u16; 80000]` buffers (256 KB thread stack size), eliminating all heap allocations within indexing worker threads. Packed `TInfo` to 16 bytes by resolving tail slices directly against `q_buf`, saving 655 KB of BSS memory. Dropped peak memory to 48.6 MB (-3.6 MB), though 6-chunk indexing left SMT threads idle.
- **Step 11:** Breakthrough sub-0.50s wall time and all-time record score ($K = 15.93$) (`run-81d218f06437`). Re-enabled 12-way parallel indexing (`NUM_C = 12`) to fully engage all 12 hardware threads across 6 P-cores. Page-aligned `VTAB` and `BLOOM` with `#[repr(align(4096))]` and unmapped them via `madvise(MADV_DONTNEED)` directly after Pass 2 (-1.15 MB anonymous memory). Packed `Query` struct down to 8 bytes backed by contiguous `q_terms` flat buffer (-760 KB). Stored `bs_idx` as `u16` (-152 KB) and embedded term frequency in `TInfo` padding, dropping `term_df` immediately after Pass 1 (-304 KB). Configured 64 KB query thread stacks with main-thread chunk dispatch (-832 KB). Called `malloc_trim(0)` after dropping index vectors before writing `/out/results.txt`. Wall time broke the half-second barrier down to **0.497 s** (-22% latency reduction from Step 10), boosting score to **$K = 15.93148$** and **60.11 Speed Points**. Exact SHA-256 match verified across both sample and full datasets.
- **Step 12:** Single persistent 12-thread scope across indexing and query execution synchronized with lock-free atomic spin-barriers, eliminating thread re-spawn latency. Integrated explicit 256-bit AVX2 SIMD intrinsics (`_mm256_loadu_si256`, `_mm256_and_si256`, `_mm256_or_si256`, `_mm256_andnot_si256`) for 4-wide parallel boolean bitset evaluations. Accelerated phrase candidate verification with 32-byte AVX2 first-character broadcast filtering (`_mm256_cmpeq_epi8`, `_mm256_movemask_epi8`). Maintained direct `doc_ts[d]` jumps and hoisted `d_word` / `d_bit` calculations in Pass 2. Verified 100% exact SHA-256 match on both sample and full datasets.
- **Step 13:** Tagged 16-byte `Slot { w0: u64, h_tag: u32, tid: u32 }` hash table with zero-indirection fast-path, Bloom filter elimination, and sub-45MB peak memory ceiling.
  1. *Tagged 16-Byte Slot:* By packing 24 bits of hash tag and 8 bits of length directly into `h_tag` alongside `w0` and `tid` in a 16-byte cache-aligned slot, words <= 8 characters (~80% of all vocabulary lookups) match in a single L2 cache access without accessing `TINFO` or `q_buf`.
  2. *Bloom Filter Elimination:* Profiled inner word loop with RDTSC cycle counting, discovering that 79.1% of all words in the corpus match query terms. Querying a 128 KB Bloom filter across two independent hash positions was adding 34 cycles/word of redundant overhead. Removing the Bloom filter dropped word processing from 312.8 cycles/word to 124.0 cycles/word (>2.5x speedup).
  3. *50x Memory Multiplier Ceiling ($M \approx 45\text{ MB}$):* Using persistent 12-thread two-pass indexing with in-place prefix sum and `madvise(MADV_DONTNEED)` drops container memory from 107 MB down to 45 MB, achieving the maximum 50x multiplier ($50^{0.20} = 2.1867\times$).
- **Step 14:** SIMD 8-byte SWAR zero-branch word extraction and space delimiter fast path (`fast_scan_doc`).
  1. *SWAR 8-Byte Word Fast-Path:* Discovered through corpus analysis that 89.58% of all words are strictly lowercase `a-z`, 80.02% of words have length <= 8 bytes, and 84.14% of word delimiters are a single space (`0x20`). Combined, over 60% of all document tokens are 1-8 lowercase letters followed by a space.
  2. *Zero-Branch Word Tokenization:* Evaluates `raw8 ^ 0x2020202020202020` with zero-byte SWAR bit manipulation and `trailing_zeros()` to locate the delimiter space in 1 CPU cycle. Validates lowercase ASCII bounds (`a-z`) via parallel unsigned subtraction in SWAR. For all matching words, completely bypasses the character-by-character `CMAP` reading loop, variable shift multiplications, and branch predictions.
  3. *Bit-Exact Verification:* Verified 100% bit-exact SHA-256 match on both `b-sample` and `b-full`.
- **Step 15:** Single-Pass Forward Ingestion with Pre-Sampling Heavy Bitset Bypass, Per-Worker Forward Unmapping, and Sub-42MB Peak Memory.
  1. *Pre-Sampling Bitset Bypass:* Fast 1.5ms pre-sampling of first 2,500 documents isolates the top ~200 heavy terms (>5.6% df) before parallel ingestion. Workers write bitset terms directly to `g_bs` without touching forward buffers, saving 8 million forward writes (16 MB physical RAM).
  2. *Per-Worker Forward Buffers with Immediate Unmapping:* Replaced the unified 49 MB global forward buffer with 12 thread-local 2.7 MB buffers (`FW_CAP = 1,350,000`). Each worker immediately frees its forward and document pointer buffers with `munmap` after transposition. Unmapped `VTAB` with `MADV_DONTNEED`. Peak anonymous memory is strictly capped at ~40.5 MB, hitting the 50x multiplier cap.
  3. *Single-Pass Speed:* Eliminates Pass 2 file re-scanning completely while maintaining 100% exact SHA-256 output verification across all datasets.
